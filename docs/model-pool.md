# Пул моделей: переключение ключей и моделей

## Как выбирается провайдер

`createProviderFromEnv` смотрит на ключи в окружении и собирает **пул
кандидатов**. Любой реальный провайдер идёт через пул, даже если кандидат один:
один путь исполнения означает, что переключение ведёт себя одинаково в
бенчмарке и в бою, а не срабатывает впервые в самый неподходящий момент.

```
AI_PROVIDER=mock        # без сети, для CI и локальной демонстрации
AI_PROVIDER=openrouter  # бесплатные модели, ~50 запросов/сутки на аккаунт
AI_PROVIDER=groq        # бесплатные модели, 14 400 запросов/сутки на аккаунт
AI_PROVIDER=gemini      # бесплатные модели, лимит по модели, не по аккаунту
AI_PROVIDER=openai      # OpenAI или любой совместимый шлюз
AI_PROVIDER=anthropic
AI_PROVIDER=pool        # всё сразу: OpenRouter → Groq → Gemini → OpenAI → Anthropic
```

Без `AI_PROVIDER` порядок автоопределения: OpenRouter → Groq → Gemini → Anthropic
→ OpenAI → mock.

## Где ещё взять бесплатные или дешёвые вызовы

Сравнение бесплатных тарифов, актуальное на момент внедрения (проверять перед
использованием — тарифы меняются):

| Провайдер | Лимит | Метрика | Заметки |
|---|---|---|---|
| **Groq** | 14 400 запросов/сутки | на аккаунт | самый широкий бесплатный пул здесь — хватает на полный прогон харнесса (~2000 вызовов) за один день; OpenAI-совместимый эндпоинт, но support structured output не гарантирован вендором — проверять `probe-models.ts` |
| **Gemini** | Flash-Lite ~1000/сутки, Flash ~250/сутки | на модель | лимит не общий на аккаунт, поэтому `buildGeminiCandidates` даёт каждой модели свой `quotaGroup`; бесплатный тариф может использовать промпты для обучения — не для чувствительных данных |
| **OpenRouter** | ~50/сутки без кредитов, 1000/сутки с $10 | на аккаунт | см. раздел ниже — уже внедрено и измерено |
| **Cerebras** | ~1M токенов/сутки | на аккаунт | не подключено; интересен скоростью инференса, а не лимитом — рассмотреть, если задержка станет узким местом |

Самый дешёвый платный резерв, если бесплатных лимитов не хватает на полный
прогон со статистикой: **DeepSeek V4** (~$0.14 / $0.28 за million input/output
токенов). Локальный инференс на этой машине не рассматривается — видеокарта
(GT 1030, 2 ГБ VRAM) не тянет ни одну полезную модель, а инференс на CPU при
64 ГБ RAM растянул бы полный прогон на 15+ часов.

Groq и Gemini подключены тем же способом, что и OpenRouter —
`buildGroqCandidates` / `buildGeminiCandidates` в
[`packages/ai/src/provider/config.ts`](../packages/ai/src/provider/config.ts).
**Прежде чем доверять им в бенчмарке, прогоните `probe-models.ts` против их
реальных моделей** — ровно то же правило, что и для OpenRouter: заявленная
поддержка JSON-схемы или устойчивость роли ничего не значит без проверки на
настоящих промптах пайплайна.

## Несколько ключей и моделей

Всё через запятую, кандидаты — декартово произведение «ключ × модель»:

```
OPENROUTER_API_KEYS=key1,key2
OPENROUTER_MODELS=model-a:free,model-b:free
AI_POOL_COOLDOWN_MS=300000
```

## Что делает пул при отказе

Отказы делятся на два вида, и это различие принципиально:

| Вид | Признак | Реакция |
|---|---|---|
| **Доступность** | любой HTTP-статус, кроме 400: лимит, квота, 5xx, сеть | кандидат уходит в кулдаун, запрос идёт следующему |
| **Способность** | 400 или невалидный JSON после всех попыток | считается качеством модели, кулдауна нет |

Смешивать их нельзя: если исчерпание квоты записать как «плохая модель», её
никогда не выведут из ротации и прогон будет биться о мёртвый эндпоинт.

**Лимиты уровня аккаунта.** Бесплатные тарифы обычно метрят аккаунт, а не
модель: OpenRouter отвечает `free-models-per-day` на *любую* бесплатную модель,
когда суточная квота исчерпана. Поэтому такой отказ уводит в кулдаун **все
кандидаты на том же ключе** — иначе пул потратит по вызову на каждую модель,
прежде чем сдаться.

## Ограничение бесплатного тарифа OpenRouter

Замерено на живом ключе: без кредитов на аккаунте доступно **порядка 50
запросов в сутки на все бесплатные модели вместе**. Пополнение на $10
открывает 1000 запросов/сутки.

Полный прогон харнесса (70 сценариев × 5 армов × ~6 вызовов) — это **~2000
вызовов**. Отсюда практический вывод:

- бесплатные модели годятся для дымовых прогонов и подвыборок (`--limit 5`);
- для замера со статистикой нужен платный ключ либо $10 кредитов на OpenRouter
  и прогон, разбитый на несколько суток.

## Выбор моделей: только по замеру

`OPENROUTER_FREE_MODELS` — не список из каталога провайдера, а результат
`bun run packages/eval/probe-models.ts`. Проба гоняет два вызова, которые
доминируют в бенчмарке (реплика персонажа и вердикт судьи), и проверяет две
вещи: возвращается ли валидный по схеме объект и держится ли русская роль.

Результат последней пробы (4 из 8):

| Модель | Вердикт |
|---|---|
| `nvidia/nemotron-3-super-120b-a12b:free` | ✅ годится |
| `google/gemma-4-26b-a4b-it:free` | ✅ годится |
| `nvidia/nemotron-3-nano-30b-a3b:free` | ✅ годится |
| `nvidia/nemotron-nano-9b-v2:free` | ✅ годится |
| `nvidia/nemotron-3.5-lightning:free` | ❌ не держит контракт |
| `google/gemma-4-31b-it:free` | ❌ не держит контракт |
| `openai/gpt-oss-20b:free` | ❌ не держит контракт |
| `inclusionai/ling-3.0-tiny:free` | ❌ не держит контракт |

Обратите внимание: `nemotron-3.5-lightning` (контекст 1M) и `gemma-4-31b-it`
крупнее нескольких прошедших моделей. **Размер контекста и число параметров не
предсказали ничего** — поэтому список пополняется только после пробы, а не по
каталогу.

Отвергнутые модели перечислены в `OPENROUTER_REJECTED_MODELS`, чтобы их не
вернули в список по ошибке.

## Почему подмена модели — это предупреждение в отчёте

Переключение спасает прогон, но может подменить модель под армом. Арм, который
обслужила одна модель, нельзя сравнивать с армом, который обслужила другая:
разница объяснится моделью, а не подходом. Поэтому:

- каждый диалог хранит модели, реально его обслужившие (`ItemResult.models`);
- сводка по варианту хранит их распределение (`VariantSummary.modelMix`);
- отчёт выводит явное предупреждение и раскладку моделей по вариантам;
- отдельный раздел «Кто обслуживал запросы» показывает успехи и отказы каждого
  кандидата.

Телеметрия берёт модель из результата стадии, а не из `provider.model`: у пула
последнее — лишь первый кандидат, и на нём учёт был бы неверным.
